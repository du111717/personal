Study Notes

学习笔记

把零散知识整理成可以回看、可以迁移、可以实践的记录。

Note 01

AI 为什么总把格式搞乱？

我开始理解，AI 不只是生成文字，也在生成结构。Markdown 与 JSON 本质上都是内容和数据的组织方式。

Markdown 更偏向给人阅读，适合标题、列表、引用和段落；JSON 更偏向给程序读取，要求字段、层级和符号都稳定。

当 AI 输出格式混乱时，往往不是它“不懂内容”，而是没有被清楚约束结构。以后写 Prompt 时，我会明确要求输出格式、字段名称和示例。

Note 02

AI 生图并不在本地运行

真正工作的其实是云端模型。本地输入 Prompt 后，通过 HTTP 请求调用 AI 能力，再返回图片或视频结果。

我逐渐明白，网页或工具里的“生成图片”按钮，本质上是在把文字请求发送到远程服务。模型在云端处理任务，再把生成结果传回来。

这让我开始理解 HTTP 请求、接口、参数和返回结果之间的关系，也知道了为什么网络、额度和等待时间会影响 AI 生图体验。

Note 03

GitHub 不只是代码网站

以前以为 GitHub 只是程序员仓库，后来发现它更像全球开发者共享知识、沉淀项目与协作的平台。

GitHub 里的仓库不仅能保存代码，还能记录版本、管理问题、展示文档，并让不同的人围绕同一个项目协作。

对我来说，它也像一个公开学习档案。每一次提交、每一个 README，都是把学习过程变得更清晰的一部分。

Note 04

第三方登录背后的逻辑

开始理解 OAuth 授权机制。很多网站并不直接保存密码，而是通过 Google 等平台完成身份验证。

第三方登录的关键不是“把密码交给网站”，而是让可信平台确认身份，再把授权结果交给当前应用。

OAuth 让我看到，登录不仅是表单提交，还涉及身份、权限、回调地址和安全边界。理解它之后，很多网站登录流程都变得更有逻辑。

Note 05

我开始真正接触编程逻辑

Python 不只是语法，更重要的是训练拆解问题、组织步骤和表达逻辑的能力。

学习 Python 时，我最有收获的不是记住某个语法，而是学会把一个问题拆成输入、处理和输出。

变量、条件、循环和函数看起来基础，但它们组合起来就是解决问题的骨架。写代码的过程，也是在训练自己更有条理地思考。

Note 06

AI 为什么会“查资料”？

开始学习 RAG 后发现，很多 AI 并不是直接记住所有知识，而是通过向量检索实时获取上下文。

RAG 的思路是先把资料切分、向量化，再根据问题检索相关内容，最后把这些内容交给模型生成回答。

这让我理解了“知识库问答”的基本逻辑：AI 的回答质量不只取决于模型，也取决于资料整理、检索效果和上下文组织。

Note 07

Prompt 本质上是一种沟通设计

好的 Prompt 不只是提问，而是在定义角色、结构、目标与输出格式，让 AI 更稳定地完成任务。

我开始意识到，Prompt 不是随便问一句，而是在设计一次沟通。要告诉 AI 它扮演什么角色、要解决什么问题、按什么结构输出。

当目标、边界和格式越清楚，结果就越稳定。Prompt Engineering 本质上也是一种把想法表达清楚的能力。
